# AlgoLens — DSA Algorithm Visualizer (Design)

Date: 2026-06-11
Status: Approved for implementation (user requested autonomous plan + complete implementation)

## Purpose

An interactive TypeScript + React web app that teaches the **intuition** behind the most
important DSA algorithm patterns. For each pattern the app provides:

1. A **step-by-step animated visualization** of a canonical example (play / pause / step / speed).
2. A plain-language **intuition** section (analogy + why it works).
3. **Time & space complexity** with a short visual/verbal justification.
4. **Pseudocode** with the currently-executing line highlighted in sync with the animation.
5. **At least 10 famous problems** (LeetCode classics) per pattern, each with difficulty and a
   one-line "how the pattern applies" hint.

## Approaches considered

| Approach | Trade-off |
|---|---|
| A. Canvas/D3 animation engine | Smooth but heavy; harder for agents to author consistently |
| B. **Step-snapshot model + SVG/div rendering (chosen)** | Each algorithm emits an array of immutable `Step` snapshots; a shared player walks them. Simple, deterministic, easy to test, perfect line-sync with pseudocode |
| C. Live interpreter tracing real JS | Cool but complex and fragile; YAGNI |

**Chosen: B.** Deterministic step arrays generated by instrumented TS implementations.

## Scope — 12 algorithm patterns × ≥10 problems each (120+ problems)

two-pointers, sliding-window, binary-search, bfs, dfs-backtracking, dynamic-programming,
merge-sort, quick-sort, heap, union-find, dijkstra, topological-sort.

## Architecture

- **Stack**: Vite + React 18 + TypeScript. No router lib (lightweight hash navigation). No UI framework — custom CSS design system.
- `src/core/types.ts` — `AlgorithmModule`, `Step<S>`, `Problem`, `Complexity` contracts.
- `src/core/useStepPlayer.ts` — play/pause/next/prev/speed/reset over a `Step[]`.
- `src/components/` — shared: `PlayerControls`, `PseudocodePanel`, `ComplexityCard`, `IntuitionCard`, `ProblemsList`, `AlgorithmPage`, `HomePage`, `Sidebar`.
- `src/algorithms/<id>/index.tsx` — one self-contained module per pattern exporting an
  `AlgorithmModule`: meta, intuition, complexity, pseudocode, `generateSteps()`, `Visualizer`,
  `problems[]` (≥10). Registered in `src/algorithms/registry.ts`.
- Each step carries: `state` snapshot (rendered by the Visualizer), `description` (narration),
  `codeLine` (pseudocode highlight index).

## Visual design (frontend-design direction)

"**Midnight blueprint**": deep ink-blue/charcoal canvas with a faint engineering-grid texture;
mint-green primary accent + warm amber secondary; display font **Bricolage Grotesque**, body
**Instrument Sans**, code **JetBrains Mono** (Google Fonts). Staggered reveal on load, smooth
CSS transitions on element movement, glowing highlights for active pointers/cells. Dark theme
only. Memorable detail: pointers/cells animate with spring-like CSS transitions and the
narration ticker types out each step's description.

## Multi-agent implementation plan

1. **Core (main session)**: scaffold app, design system CSS, core types, player hook, shared
   components, home page, and one exemplar algorithm (`two-pointers`) defining the authoring
   pattern.
2. **Fan-out (workflow, 11 agents)**: one agent per remaining algorithm, each writing only its
   own `src/algorithms/<id>/` folder following the exemplar contract — disjoint files, safe to
   parallelize.
3. **Integration (main session)**: registry wiring, `tsc`/`vite build` fix pass, verification.

## Error handling & testing

- Step generators are pure functions; a build-time check ensures every module has ≥10 problems
  and ≥1 step.
- Verification = `npm run build` (tsc + vite) passes and the app renders each algorithm page.

## Out of scope (YAGNI)

User accounts, progress tracking, code execution sandbox, mobile-first optimization, light theme.
